# EtherZar (Ethereum Bazaar)

EtherZar is an Ethereum-based marketplace for selling encrypted digital content via auctions. Users connect with MetaMask (Sepolia testnet only for school/testing) and create auctions that reference files stored on IPFS. Auctions are backed by on-chain smart contracts; bidding and settlement happen on SepoliaETH while file storage and retrieval use IPFS.

## Key Concepts

- **Network:** SepoliaETH (testnet) — the application currently targets Sepolia for testing and coursework.
- **Auth:** Users must connect their MetaMask wallet to access the app.
- **Storage:** Digital content is stored on IPFS. Files may be uploaded through the app or provided as an existing IPFS handle.
- **Encryption:** Files are symmetrically hashed/encrypted with a passphrase supplied or generated by the user.
- **Contracts:** Each auction deploys a smart contract containing metadata and security checks; auction flow and funds are handled on-chain.

## Features

- Create auctions with: name, end timestamp, optional minimum bid, Markdown description, symmetric key/passphrase, and file (upload or existing IPFS handle).
- Two upload modes:
  - Mode A: App uploads the user file to IPFS and stores the IPFS handle.
  - Mode B: User supplies an existing IPFS handle (for large files or external uploads).
- Bidding via MetaMask (payable transactions).
- Owner reveals passphrase after auction ends to deliver decryption secret to highest bidder.
- Refunds for non-winning bidders.
- Search auctions by name (local DB) or by smart contract address.

## Auction Creation Workflow (high level)

1. User connects MetaMask (Sepolia).
2. User fills auction form: `Name`, `End Timestamp`, `Min bid` (optional), `Description` (Markdown), `Passphrase/key` (or auto-generate), and file (upload) or IPFS handle.
3. If uploading a raw file (Mode A):
   - App generates SHA-256 of the original file and SHA-256 of passphrase.
   - The file is symmetrically encrypted/hashed with the passphrase client-side.
   - App uploads the (encrypted) file to IPFS and obtains an IPFS handle.
4. If user provided an IPFS handle (Mode B):
   - User must supply the passphrase used to derive the encrypted file.
5. The app deploys the auction smart contract to Sepolia with constructor args: `minBid`, `name`, `description`, `original_file_hash`, `ipfs_handle`, `passphrase_hash`, `end_at_ts`.
6. User confirms the deployment in MetaMask and the app waits for contract confirmation.
7. After deployment the app stores: `name`, `description`, and `contract address` in the app database (for search/listing) and redirects to `/auction/{contract_address}`.
8. Optionally store the symmetric passphrase in the user's local storage (user-choice) to allow autofill for later actions.

## Smart Contract (spec)

Stored data (set during constructor or by contract logic):

- `owner` (address)
- `name` (string)
- `description` (string)
- `originalFileHash` (string) — SHA-256 of original file
- `ipfsHandle` (string)
- `passphraseHash` (string) — SHA-256 of passphrase
- `endAt` (uint256 timestamp)
- `maxBidder` (address)
- `maxBid` (uint256)
- `state` (enum { Bidding, WaitingPassphrase, Completed })
- `bidders` mapping(address => uint256) — total value each address bid (excluding highest bidder if desired)

Public/External functions:

- `checkStatus()` — returns metadata (maxBid, endAt, name, description, owner, etc.). If current time >= `endAt`, transition state to `WaitingPassphrase`.
- `bid()` payable — place a bid while `now < endAt` and `state == Bidding`.
- `enterPassphrase(bytes passphrase)` — callable by owner only, after `endAt` and `state == WaitingPassphrase`. Verifies `sha256(passphrase) == passphraseHash`:
  1. set `state = Completed`.
  2. transfer `maxBid` to `owner`.
- `givePassphrase()` — callable by `maxBidder` if `state == Completed`; returns the passphrase and IPFS handle (or emits an event containing the handle and passphrase proof).
- `refund()` — callable by bidders (not the max bidder) when `state == Completed` and they have a positive bid balance; sets their recorded value to 0 and transfers funds back.

Notes:

- Implement checks so the highest bidder cannot refund the winning bid after owner was paid (exclude `maxBidder` from refundable mapping or check on refund call).

## UI Behavior

- Main page requires MetaMask connection.
- Search bar / contract address field supports:
  - search by name in the app database
  - lookup by contract address on Sepolia
- Listings: default sort newest → oldest; search filters apply.
- Auction page shows current status, highest bid, time remaining, and action buttons:
  - Bid (opens MetaMask transaction)
  - Owner: Enter passphrase (after end)
  - Bidders: Refund (after completion)
  - Winner: Reveal/download decrypted file — app attempts to fetch IPFS file, decrypt in-browser, verify SHA-256, and offer download; alternatively show `ipfsHandle`, `passphrase`, and `originalFileHash` so user can decrypt outside the app.

## IPFS & Encryption Modes

- Mode A (app uploads): user uploads file; app hashes, encrypts with passphrase client-side, uploads to IPFS and stores handle.
- Mode B (user provides handle): suitable for large files; user must provide the passphrase used to symmetrically encrypt the file previously uploaded to IPFS.

## Testing / Notes

- The app is intended for Sepolia testnet only (for school/testing). Users must switch MetaMask to Sepolia.
- Sensitive secrets (passphrases) are only stored locally if the user opts in; the smart contract only stores the hash of the passphrase.
- Verify client-side SHA-256 calculations and encryption before submitting contracts.

## Security considerations

- Always validate inputs client-side and on-chain where applicable.
- Do not store raw passphrases on the server.
- Use well-reviewed cryptographic libraries for hashing/encryption client-side.
