Úvod

Doposud váš operační systém pracoval s pamětí jako s jedním „plochým“ prostorem bez jasné struktury. Programy jste načítali na pevné adresy a spouštěli bez jakékoliv správy paměti.

V této úloze zavedeme jednoduchý paměťový model založený na statických partitionách (fixed partitioning).

Tento přístup není pouze historickou zajímavostí (např. IBM OS/360), ale byl využíván i v relativně moderních systémech, jako je Windows CE / Windows Mobile, kde byly aplikace často mapovány do předem definovaných paměťových oblastí.

Cílem je vytvořit jednoduchý, deterministický paměťový model, který umožní:

  • spouštění více programů současně
  • oddělení jejich zásobníků (stacků)
  • přípravu na integraci plánovače s časovačem (příští úloha)

Výchozí stav

Aktuálně:

  • kernel je načten přibližně na:
KERNEL_OFFSET equ 0x1000
  • stack kernelu:
mov ebp, 0x80000
mov esp, ebp
  • programy spouštíte pomocí:
void (*func)() = (void(*)())addr;
func();

Cíl

Po dokončení úlohy bude váš OS:

  • rozdělovat paměť na pevné bloky (partitiony)
  • přiřazovat každý blok jednomu vláknu/programu
  • inicializovat stack pro každé vlákno
  • umožňovat bezpečné přepínání kontextu mezi vlákny

Navržený paměťový model

Paměť rozdělte například na pevné bloky:

0x00000000 - 0x0009FFFF   BIOS / low memory
0x00001000 - ...          KERNEL

0x00100000 - 0x0010FFFF   PROCESS 0 (64 KB)
0x00110000 - 0x0011FFFF   PROCESS 1
0x00120000 - 0x0012FFFF   PROCESS 2
...

Konstanty

Doporučená konfigurace:

#define KERNEL_BASE      0x00001000

#define PROC_BASE_START  0x00100000
#define PROC_SLOT_SIZE   0x00010000   // 64 KB
#define MAX_PROCESSES    8

Výpočet adres

#define PROC_BASE(i) \
    (PROC_BASE_START + (i) * PROC_SLOT_SIZE)

#define PROC_STACK_TOP(i) \
    (PROC_BASE(i) + PROC_SLOT_SIZE - 4)

Struktura paměti procesu

Každý proces bude mít:

+----------------------+
| STACK (roste dolů)   |
|                      |
|                      |
|----------------------|
| DATA / BSS           |
|----------------------|
| CODE (.text)         |
+----------------------+
base

Úkol 1: Správa partition

Implementujte jednoduchou tabulku:

struct partition {
    uint32_t base;
    int used;
};

Inicializujte pole partition podle MAX_PROCESSES.

Úkol 2: Úprava scheduleru / vláken

Rozšiřte strukturu vlákna (struct gt):

struct gt {
    ...
    uint32_t esp;
    uint32_t eip;

    uint32_t base;
    uint32_t stack_top;
};

Úkol 3: Vytvoření vlákna

Při gt_create():

  1. Najděte volný slot
  2. Nastavte:
gt->base = PROC_BASE(i);
gt->stack_top = PROC_STACK_TOP(i);
  1. Inicializujte stack:
  • nastavte ESP na stack_top
  • připravte návratovou adresu (např. gt_exit)
  1. Nastavte EIP na entry point

Úkol 4: Úprava CLI (load / run)

Změňte chování:

> exec test.bin

→ systém:

  • najde volný slot
  • načte binárku na PROC_BASE(i)
  • vytvoří vlákno
  • předá řízení scheduleru

Úkol 5: Oddělení stacků

Ověřte:

  • každé vlákno má vlastní stack
  • nedochází ke kolizi paměti
  • přepínání kontextu funguje správně

Testovací scénář

  1. Spusťte více programů současně, doporučuji si vytvořit jednoduchou aplikaci zobrazující čas nebo rotující hvězdičku (ze znaků ... /|-)

  2. Každý program:

    • zapisuje na stack
    • vypisuje svou identitu 3. Sledujte:
    • zda se nepřepisují
    • zda běží paralelně (RR)

Bonus

  • jednoduchý „kill“ procesu (uvolnění slotu)

Poznámka: Způsoby spouštění programů v tomto modelu

V rámci tohoto cvičení existuje více způsobů, jak řešit umístění a spouštění programů v paměti. Vzhledem k tomu, že nepoužíváme paging ani relocace, budeme pracovat s následujícími zjednodušenými přístupy:

Varianta A – pevná adresa pro každý slot

Každý paměťový slot má pevně danou adresu (PROC_BASE(i)), na kterou je program nahráván. Program musí být při překladu (linkování) nastaven tak, aby počítal s tím, že poběží právě na této adrese.

To znamená, že:

  • linker script určuje konkrétní adresu .text segmentu (např. 0x00100000)
  • pro každý slot může existovat samostatná verze binárky
  • operační systém pouze nahraje binární soubor na správnou adresu a spustí jej

Tento přístup je velmi jednoduchý a nevyžaduje žádnou podporu relocace, ale není flexibilní – program je pevně svázán s konkrétní adresou v paměti.

Varianta B – jednotná adresa + kopírování

Alternativně lze všechny programy překládat pro jednu společnou adresu (např. 0x2000). Při přepnutí kontextu operační systém:

  • zkopíruje obsah příslušného paměťového slotu na tuto adresu
  • nastaví stack a registry
  • spustí program

Každý program tak běží vždy na stejné adrese, bez nutnosti řešit relocaci nebo více verzí binárek.

Nevýhodou je nutnost kopírování paměti při každém přepnutí, což je neefektivní. Tento přístup je však konceptuálně jednoduchý a může být vhodný pro experimentální účely.
